The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

## [1.2.0] - 2026-11-02

Services, the API calls of the project, with `generate:service` on vueg 2.3, in Vue 2 and Vue 3 projects.

### Added
- `generate:service [name]`: a service in `src/services/`, a module of API calls with `fetch` (`getAll`, `getById`, `create`, `update`, `remove` on `/api/<name>`), like `vueg service`, with `--path`, `--ts`, `--test` (a Vitest test), `--blank`, `--force` and `--dry-run`. The service has no Vue code: it works the same in Vue 2 and Vue 3 projects. File names in kebab-case (`UserProfile` → `user-profile.service.js`); an existing service or test is overwritten only after confirming. `vue add` adds the `generate:service` and `g:s` scripts (`--ts` from the TypeScript answer); in an installed project, `vue invoke @ashetm/vue-cli-plugin-component-generator` adds them ([#63](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/63)).

### Changed
- vueg `^2.3.0`, which has `service()` ([#63](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/63)).

## [1.1.0] - 2026-11-02

A test, a story and a Pug template with components and views in Vue 3 projects, on vueg 2.2: `--test`, `--story`, `--template pug`.

### Added
- `generate:component` and `generate:view` take vueg 2.2's `--test` (a Vitest test next to the component or view), `--story` (a Storybook story next to it) and `--template pug`, in Vue 3 projects; in a Vue 2 project they are refused (*Vue 3 only*), like `--emits`. `--no-template` keeps working in both. `--template` without a value is refused. When only the test or the story exists, the overwrite question names it (`src/components/Card.spec.js exists!`) ([#60](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/60)).

### Changed
- Vue 3 components are generated by vueg `^2.2.0` (vuegc 2.1), which also refuses `--no-template` when the component wouldn't compile: add `--props`, `--emits` or `--options` ([#60](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/60)).

## [1.0.0] - 2026-11-01

Components are generated by [vueg](https://github.com/AsheTM/npm-vueg), as **single `.vue` files**, in Vue 2 and Vue 3 projects, with vueg's options; and views with their route (`generate:view`). **Breaking:** see [Migrating from 0.2](README.md#migrating-from-02).

### Added
- `generate:component` has [vueg](https://github.com/AsheTM/npm-vueg)'s options: `--path` (inside `src/`), `--style` (`css`, `scss`, `sass`, `less`, `stylus`), `--scoped`, `--module`, `--props`, `--blank`, `--no-template`, `--no-script`, `--no-style`, `--force`, `--dry-run`, and in Vue 3 projects `--emits`, `--ts` and `--options` ([#45](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/45)).
- `generate:view [name]`: a view in `src/views/` (`--path` is a sub-folder of it) and its route in the router, lazy loaded, like `vueg view`, in Vue 2 and Vue 3 projects. `--route /path` chooses the route's path (default: the folder and the name in kebab-case), `--no-route` leaves the router as is; the component options work the same. Nothing is written if something is wrong: no router, a route path or name already used, an existing view without `--force` ([#46](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/46)).

### Changed
- **Breaking:** components are generated by vueg, as **one `.vue` file**: `generate:component admin/user-card` writes `src/components/admin/UserCard.vue` instead of 4 files (`user-card/user-card.{vue,html,js,css}`). Vue 2 projects get vueg 1's component (Options API), Vue 3 projects vueg 2's (`<script setup>`), from the installed Vue version, or the one in `package.json`. Names are in PascalCase (`user-card` → `UserCard`). An existing component is still overwritten only after confirming, or with `--force` ([#45](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/45)).
- **Breaking:** `--script`, `--view` and `--root-dir` are removed, and so are the Vue 2 class components (`vue-property-decorator`). Using a removed option says so, and how to update the scripts of `package.json` ([#45](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/45)).
- `vue add` asks for the components folder inside `src/` (`components` by default; `./src/components` is understood), the style among the installed pre-processors (Sass: `scss` and `sass`, Less, Stylus), and in Vue 3 projects with TypeScript whether components are in TypeScript. It adds 4 scripts: `generate:component` and `generate:view`, with `--style` (always, since vueg 1 defaults to `scss`), `--path` and `--ts` from the answers, and their shortcuts `g:c` and `g:v`. In a project set up by 0.2, `vue invoke @ashetm/component-generator` replaces the old scripts ([#47](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/47)).
- README for 1.0.0: installation and its questions, components and views with real examples (Vue 2 and Vue 3, the route added), the options, how the Vue version is found, errors, and **Migrating from 0.2** ([#48](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/48)).
- Errors (invalid name, unknown option, unsupported style, a Vue 3 option in a Vue 2 project…) print a message and exit with code 1, without a stack trace and without generating anything ([#45](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/45)).
- **Node 20.19 or later** (`^20.19.0 || >=22.12.0`): Node 18 has been end-of-life since April 2025. CI runs on Node 20, 22 and 24 ([#44](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/44)).
- Tests run with mocha and chai (`npm test`), and the coverage with c8 (`npm run test:coverage`), instead of the built-in `node:test` runner ([#44](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/44)).

### Fixed
- The options of the scripts can be overridden: `npm run g:c -- Card --style less` passes `--style` twice (the script's, then yours), and failed with `--style needs a value`. An option given twice now takes its last value (`--style less`, `--path ui`, `--ts false`). The scripts end with `--style`, so the name after them is never read as the value of `--ts` ([#56](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/56)).
- The `g:c` shortcut passes the options on: `npm run g:c -- Card --props title` generated `Card` without its props, since the inner `npm run` took `--props` as its own option. The shortcuts are now `npm run generate:component --` and `npm run generate:view --` ([#54](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/54)).

## [0.2.0] - 2026-11-01

Fixes: `vue add` works in JavaScript projects, the name works on the command line, and the script matches the project's Vue version. Generated files change for names like `UserCard` (now `user-card/user-card.*`) and for Vue 2 projects.

### Added
- Tests with the built-in `node:test` runner and a fake Vue CLI API, run in temporary projects: `npm test`, and `npm run test:coverage` for the coverage ([#1](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/1)).
- CI: GitHub Actions run `npm ci` and `npm test` on every pull request into `develop` or `master` and every push to `develop`, on Node 18, 20, 22 and 24, on Ubuntu and Windows. Dependabot: a weekly pull request into `develop` for npm packages and GitHub Actions ([#2](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/2)).
- MIT `LICENSE` file, in the repository and the npm package (`package.json` already said MIT) ([#16](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/16)).

### Changed
- A project `.npmrc` pins the registry to registry.npmjs.org, also for `@ashetm` packages: installs, the lock file and `npm publish` no longer depend on the developer's own npm config (no token in it; npm never packs it) ([#3](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/3)).
- `vue add` no longer adds an empty `devDependencies` to the project's `package.json`; question typos fixed ("What language do you want to work with?") ([#13](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/13)).
- `package.json`: repository, issues and homepage links to the repository's current name (`npm-vue-cli-plugin-component-generator`); `files`, so only the plugin, its templates and docs are published (not the tests, CI and editor files); `engines`: Node 18 or later; a description and keywords that say what it does ([#14](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/14)).
- `package-lock.json` regenerated against registry.npmjs.org: lockfile version 3, and the package version in sync (it said 0.1.0) ([#15](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/15)).
- README: the badges show this package (version, downloads, CI, license) instead of `vue-cli-plugin-vue-component-generator`, another author's package; installation with `vue add` or npm + `vue invoke`; credit to the project the README started from; license ([#17](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/17)).
- README usage: components are generated with `npm run generate:component [name]` (it said `vue invoke`, which re-runs the installation); the installation questions and the scripts they add, name rules, a real example of the 4 generated files, the script for each Vue version, the options and their defaults, development ([#18](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/18)).
- CHANGELOG in Keep a Changelog format ([#19](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/19)).

### Fixed
- `vue add` no longer crashes in JavaScript projects (`Cannot read properties of undefined (reading '0')`): without TypeScript, the language question isn't asked and the components are in JavaScript ([#4](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/4)).
- `generate:component user-card` (the name on the command line, with optional sub-folders: `admin/user-card`) no longer crashes (`The "path" argument must be of type string`), and the command works without its options, with defaults: `--script js`, `--style css`, `--view html`, `--root-dir ./src/components`. The component is generated in the project, whatever the current directory ([#5](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/5)).
- Component names are no longer lowercased: `UserCard`, `userCard`, `user-card` and `user_card` all give the files `user-card/user-card.*`, the class `.UserCard` and the name `UserCardComponent` (`UserCard` gave `usercard/usercard.*`, `.Usercard` and `UsercardComponent`) ([#6](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/6)).
- The script matches the project's Vue version (from its `package.json`): `defineComponent` for Vue 3 (and when Vue isn't listed); for Vue 2, a plain object in JavaScript, `Vue.extend` in TypeScript, or a class component when the project uses `vue-property-decorator`. The JavaScript template was Vue 3 only and the TypeScript one Vue 2 only ([#7](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/7)).
- Overriding an existing component replaces only its generated files: the other files of its folder (tests, stories…) are kept, instead of deleting the whole folder. The confirmation defaults to *no* ([#9](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/9)).
- Cancelling the name prompt (Ctrl+C, Escape) stops quietly instead of crashing (`Cannot read properties of undefined (reading 'split')`). An empty or invalid name (not starting with a letter, other characters than letters, digits, `-` and `_`, or a `.`/`..` folder) is refused with a clear message, in the prompt and on the command line, instead of creating files named `.vue`, `.html`… ([#10](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/10)).
- A components root directory with spaces (`./src/my components`) is quoted in the `generate:component` script, instead of being split into several arguments ([#11](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/11)).
- `vue add` finds TypeScript and Sass in `dependencies` too (not only `devDependencies`), and recognizes the `sass` package (Dart Sass): those projects get the script and style questions ([#12](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/12)).
- Generated files always have LF line endings, and TypeScript components no longer keep `// @ts-ignore` when the plugin comes from a Windows checkout ([#8](https://github.com/AsheTM/npm-vue-cli-plugin-component-generator/issues/8)).

## [0.1.0] - 2021-06-25

First release.

### Added
- `vue add @ashetm/vue-cli-plugin-component-generator` asks for the components root directory, the script language (when TypeScript is installed) and the style language (when Sass is installed), and adds the `generate:component` and `g:c` scripts to the project.
- `generate:component` asks for the component name and generates 4 files in its own folder: the `.vue` file and its separate template (`.html`), script (`.js` or `.ts`) and style (`.css`, `.scss` or `.sass`).
